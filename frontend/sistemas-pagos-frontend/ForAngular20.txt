
In Angular 20, the traditional *ngFor structural directive has been superseded by the new @for built-in control flow syntax. While *ngFor still functions for backward compatibility, the recommended and more idiomatic approach in Angular 20 and later versions is to use @for.
Understanding the Shift:

    *ngFor (Older Syntax): This structural directive, prefixed with an asterisk, iterates over a collection and renders a template for each item. It's often used with variables like index, first, last, even, and odd to provide context within the loop. 

Código

    <li *ngFor="let item of items; let i = index">
      {{ i }}: {{ item }}
    </li>

    @for (Angular 20+ Syntax): This new block-style syntax offers a more readable and JavaScript-like way to handle loops directly within your templates. It replaces the need for the asterisk and provides a clearer structure for control flow. 

Código

    @for (item of items; track item.id) {
      <li>{{ item }}</li>
    } @empty {
      <p>No items found.</p>
    }

Key Features of @for:

    Readability:
    The block-style syntax is generally considered more intuitive and easier to understand, especially for developers familiar with JavaScript's for...of loops.
    Built-in @empty block:
    This allows you to define content to be rendered when the collection being iterated over is empty, eliminating the need for a separate *ngIf.
    Mandatory track clause:
    The track clause is now required with @for to specify a unique identifier for each item. This significantly improves performance by allowing Angular to efficiently re-render only the changed items in the collection. 

In summary: While *ngFor is still technically present in Angular 20 for legacy code, the framework strongly encourages the adoption of the new @for built-in control flow syntax due to its enhanced readability, built-in empty state handling, and mandatory performance optimization with trackBy.
